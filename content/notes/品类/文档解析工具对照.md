# 文档解析工具对照：Docling 与 MinerU

把 PDF、Office 文件和扫描件交给 agent 之前，先要把它们转成结构清楚的文本。这一步做得好不好，往往比后面用哪种检索更影响效果。

## 两个主要候选

| | [[Docling]] | [[MinerU]] |
|---|---|---|
| 出身 | IBM 研究院发起，现属 LF AI & Data 基金会 | OpenDataLab |
| 许可证 | MIT | Apache-2.0 加附加条款（超大规模商用需另行授权） |
| 星标（2026-11-26） | 约 7.1 万 | 约 8.4 万 |
| 强项 | 格式覆盖最广（Office、HTML、邮件、音频转写等），框架和 MCP 接入齐全 | 中文 PDF、扫描件、复杂版面、表格和公式 |
| 输出 | Markdown、HTML、无损 JSON | Markdown、JSON |

## 怎么选

- 资料以中文 PDF 和扫描件为主：先试 MinerU。
- 格式杂、英文多，或者想直接接 LangChain、LlamaIndex、MCP：先试 Docling。
- 两者都免费、都能本地跑。真正可靠的办法是挑几份有代表性的样例，用两个工具各转一遍，对比表格、标题层级和阅读顺序。

## 解析之后

推荐的轻量流程：

1. 解析成 Markdown，保留表格、标题层级和图片引用。
2. 按主题或文档类型分目录，每份文件开头写好元信息（来源、日期、适用范围）。
3. 根目录放 [[AGENTS-md|AGENTS.md]]，写清哪类内容在哪个目录。agent 先用文件搜索取内容，见 [[Agentic搜索]]。
4. 文档多了再接检索层：[[RAGFlow]] 自带解析和 API/MCP；单份长文档的精确定位用 [[PageIndex]]。

如果嫌整套平台太重，只用解析工具加文件夹就能起步，也不会被某个平台锁死。
