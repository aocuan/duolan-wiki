# 本体与语义层工具对照

「本体」这个词在开源里至少对应四种工具。它们解决的问题不同，不要拿一个替代另一个。星标截至 2026-11-26（太平洋时间）。

## 四类工具

1. **建模语言 / schema 即代码**：[LinkML](https://github.com/linkml/linkml)（Apache-2.0，约 700 星）。用 YAML 描述类型和关系，再生成 DDL、JSON Schema 等。它管的是「形状对不对」，适合在设计阶段当唯一的手改源，生成物不手改。它不管谁有权改哪条数据。
2. **语义层 / 读侧 grounding**：[[auto-ontology]]（Apache-2.0，约 1.5 万星）。从元数据自动生成概念、指标和关系，让 agent 查数据时口径一致、能说出出处。它解决「读准」，不解决「受控地改」。
3. **知识图谱推理与检索**：[OpenSPG/KAG](https://github.com/OpenSPG/KAG)（Apache-2.0，约 9,200 星）。基于 OpenSPG 引擎和大模型，用逻辑形式引导多跳推理和检索，偏专业领域问答。[[Cognee]]、[[Graphiti]]、[[LightRAG]] 则从记忆或 RAG 一侧做图。
4. **抽取与校验**：[[OntoSmith]] 这类工具把文本抽成三元组，再按本体规则过闸。它是写入图谱前的质量关，不是业务写回平台。

## 和操作本体的关系

[[操作本体]] 要的是对象、链接、动作和权限，重点在「受控写回」：agent 只能通过带闸门的动作改数据，改完留审计。上面四类工具大多停在读侧或设计时，动作、权限和审计通常还要自己补。概念边界见 [[基础本体]]。

## 怎么用

- 设计阶段：用 LinkML 这类建模语言固定类型和关系。
- 让 agent 读数据：加一层语义层，给指标和实体统一口径。
- 让 agent 改数据：单独做动作服务，按动作授权并记录审计，不要直接给数据库账号。
