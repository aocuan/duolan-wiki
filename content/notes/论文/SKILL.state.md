# SKILL.state

[SKILL.state](https://arxiv.org/abs/2608.26263)（有第 2 版）是 Google 的 runtime 论文，不是 skill 进化论文。它管的是 skill 如何跑得很长，而 [[WikiSkill]] 管的是 skill 如何积累。两篇切的是生命周期的两头，不要混。

## 论文在做什么

主张是：不要把整段对话历史塞进下一步。每一步只给三样东西：不可变的 skill 说明书、当前的结构化状态、最新观察。模型产出推理过程和一段状态补丁以及动作；运行时校验并合并后，推理过程立刻丢掉。这样提示词不随步数线性膨胀，总消耗按步数增长，而完整transcript 的做法会按步数平方增长。

和常见「结构化状态加完整对话」的框架相比，这里把对话记录当成用过就丢的东西，只有状态被当作充分统计。

## 主张与边界

作者报告在合成环境和部分公开榜上，用更少的 token 达到更高或相近的准确率。局限也包括：需要事先有固定结构；当时没写进状态的观察会丢掉；审计或复盘这类「历史本身就是答案」的任务不适合；对小模型可能还要约束解码。公开榜的收益，有一部分也可能来自「把失败记进状态」而不是架构本身。

## 有没有代码

没有官方代码仓库。附录给了运行时说明，不要把社区里的同名项目默认当成官方实现。

## 可借鉴的点

长任务里，把「当前事实」写成可校验的状态，而不是无限追加对话。这和短的 [[AGENTS-md|AGENTS.md]]、薄的 [[Skills]] 是同一方向：每次只喂下一步真正需要的东西。
