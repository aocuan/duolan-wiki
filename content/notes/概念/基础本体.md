# 基础本体

「本体」至少有三条经常被混在一起的路，名字像，目的差很多。

1. **基础本体 / 哲学本体**：追问什么算对象、什么算事件、角色和关系有何差别，给概念建模一个共用骨架。巴西 UFES / NEMO 实验室的 [UFO（Unified Foundational Ontology）](https://doi.org/10.3233/AO-210256) 是这条路上的代表，还有 BFO、DOLCE 等。它们服务的是建模语言和论文，不负责谁能改业务状态、改完怎么留痕。
2. **语义网 / 知识图谱**：用 OWL、RDF 这类形式把知识连起来，便于查询和推理，默认偏「读」。
3. **[[操作本体]]**：对象、链接、动作、权限和审计写回。核心不是把世界分类完毕，而是让业务状态只能受控地改变。

不必在这三条里选一个当信仰。若目标是让人和 agent 一起改业务对象，主线应是操作本体；基础本体最多在「这个概念到底是不是同一类东西」时拿来澄清，不要把它当成运行时规范。图检索和问答仍然是另一层，见 [[企业知识库开源选型]]。
