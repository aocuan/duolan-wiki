# 个人知识库怎么搭

个人知识库不必三选一。现在更常见的做法是：同一个 Markdown 仓库，本地用带双链的编辑器写，需要时发布成网站，同时给 AI 当检索库。思路见 [[LLM知识库]]。

## 一套就够用的结构

- **本地写作**：笔记是普通 Markdown。用 Git 同步到公开或私有仓库。不宜公开的日记放进被忽略的目录，不要提交。
- **发布成网站**（可选）：[Quartz](https://github.com/jackyzha0/quartz)（MIT，约 1.4 万星，截至 2026-11-17，太平洋时间）为这种双链笔记设计，反链、图谱和搜索都比较现成。软件文档站生成器也能用，但双链往往要自己补。
- **给 AI 用**：根目录放 [[AGENTS-md|AGENTS.md]] 和 [llms.txt](https://llmstxt.org/)，写清目录和公开范围。安装 [[obsidian-skills]]（MIT，约 5.4 万星）这类技能，让编码工具按笔记格式读写。若需要跨会话记忆，再考虑 [[Basic-Memory]]。等库的结构稳定了，可以再试 [[claude-obsidian]] 这类由模型维护整个库的方案。

## 不必一上来就做的

- 不要先上重型企业检索平台。那是多人、权限和源系统同步的问题，见 [[企业知识库开源选型]]。
- 不要先造一层花哨的 agent 记忆。先让模型能按文件名、标题和链接找到原文，见 [[Agent记忆与聊天记录工具]]。
- 不要把内部材料和未脱敏的草稿放进公开仓库。
